## [3.2.0](https://github.com/AhmedOsman101/commit-sage-cli/compare/v3.1.0...v3.2.0) (2026-10-25)


### What's changed for the users

- **Breaking changes are first-class.** Generated messages now mark them the way the ecosystem expects — `!` before the colon and/or a `BREAKING CHANGE:` footer:

```git-commit
feat(api)!: remove deprecated v1 endpoints

BREAKING CHANGE: /v1/* routes are gone; clients must migrate to /v2/*.
```

The `!` alone is enough; the footer is optional, and release tooling reads both as a major bump either way.

- **Reverts follow the spec's recommendation.** Undoing a commit produces `revert: <original headline>` with a `Refs:` footer carrying the reverted SHAs, so history pairs the revert with the release it rolled back.

- **`--offline` output is always typed.** The static generator no longer emits bare descriptions when it can't classify a change — those get a `chore:` prefix instead:

```bash
$ commit-sage generate --offline
chore: update a.ts and helpers.ts
```

`chore` maps to no release in SemVer tooling (no patch, no minor), so unclassifiable churn can't bump your version by accident.

- **Smarter `docs` typing.** `docs` now means "changes that document the project or code" — README, manpages, guides, CHANGELOG, code comments, any file type — instead of "any `.md` file is `docs`". Scopes get explicit guidance too, so generated messages lean on them when they help.

- **Subject budget.** Generated subjects aim for ~50 characters with a hard limit of 80 — short where it counts, never cut mid-thought.

- **All six languages, same rules.** The built-in translations (ru, zh, ja, de, fr) now carry the exact instructions the English template does; previously they only included a subset, so a Japanese run could miss rules an English run followed.

- **Nothing to migrate.** No new flags, config keys, or prompts — every change lands purely in how messages are written and typed.

## [3.1.0](https://github.com/AhmedOsman101/commit-sage-cli/compare/v3.0.0...v3.1.0) (2026-10-12)

### What's changed for the users

- **Groq, ready to go.** `groq` is a built-in preset — set a key and pick a model; nothing else to configure:

```bash
export GROQ_API_KEY='gsk_...'
commit-sage generate --model groq/openai/gpt-oss-120b
```

`groq/qwen/qwen3-8b-27b` is the lighter sibling under the same free-tier limits — handy when you want commit messages fast instead of thorough.

- **Any OpenAI-compatible gateway, by name.** Point the tool at a router or proxy you already use, and address it like a built-in provider:

```bash
export OMNIROUTE_API_KEY='...'
commit-sage generate --model omniroute/kimi-k2
```

```json
{
  "providers": {
    "omniroute": {
      "baseUrl": "https://gateway.example.com/v1",
      "apiKey": "$OMNIROUTE_API_KEY",
      "apiType": "openai-chat",
      "headers": { "X-Custom-Auth": "abc" }
    }
  }
}
```

`apiType` picks the wire (`openai-chat`, `openai-responses`, `anthropic`), `headers` sends extra headers (gateway auth, attribution), and `useApiKey: false` — or a keyless local host (`localhost`, `*.local`, `*.internal`) — sends no `Authorization` header. Miss the `baseUrl`, and you get a configuration error naming `providers.<name>.baseUrl` instead of a crash mid-run. No release needed for the next gateway you try.

- **Reasoning levels that tell the truth.** Each provider accepts only what its API honors (xAI is `low|high`; Anthropic's `low…max` without `none`; Gemini's `minimal…high`), and the JSON schema flags the rest in your editor while the value you set still goes through as written — you own what a gateway does with it. Unknown gateways accept the full set (`none`, `xhigh`, `max`, `ultra` included). Setting `reasoning: true` / `"default"` keeps the provider's own default with reasoning on: temperature is omitted instead of sent to a model that rejects it, and no level is forced.

- **Gemini thinking, first-class.** New keys, family-gated the way Google's API expects: `thinkingLevel` (`minimal`–`high`, default `low`) for `gemini-3*`, `thinkingBudget` (`0` off, `-1` lets the model decide, Pro models floor at 128) for `gemini-2.5*`. `gemini-2.0*` and Gemma send neither, silently. Thinking tokens are drawn from `maxOutputTokens`, so a big budget can starve the message — the existing truncation retry still doubles the budget to compensate.

- **Fewer dependencies, same behavior.** Five provider SDKs are gone (`deepseek`, `mistral`, `moonshotai`, `xai`, and `vercel-minimax`), folded into the OpenAI client the tool already ships — fewer packages to audit and a slightly smaller source install. Prompts, provider names, and request behavior are unchanged, and `anthropic`, `google`, `ollama`, `openai`, and `openrouter` keep their dedicated packages. (Compiled binary size is essentially flat — same-machine build went 92.8 → 92.1 MB on linux-x64 — so expect no download-size surprise either way.)

- **Nothing to migrate.** Existing configs load as-is — every key in this release is additive. One edge case: keyless configs relying on the LLM SDK's own env fallback now read `MOONSHOTAI_API_KEY` (was `MOONSHOT_API_KEY`) for `moonshotai` and `ZAI_API_KEY` (was `OPENAI_API_KEY`) for `zai`. Set the key in `providers.<name>.apiKey` (or under the new name) if you rely on it.

## [3.0.0](https://github.com/AhmedOsman101/commit-sage-cli/compare/v2.3.0...v3.0.0) (2026-10-10)

> **⚠ BREAKING CHANGES**
>
> The runtime moves from Deno to Bun. The CLI itself is unchanged — same
> subcommands, flags, config file, and exit codes — but distribution changes:
>
> - Linux binaries are renamed: `commit-sage-linux-x64` ->
>   `commit-sage-linux-gnu-x64` (same for arm64). Update any pinned URLs.
> - New musl variants (`commit-sage-linux-musl-*`) for Alpine and minimal
>   containers.
> - macOS, Windows, DMG, and installer names are unchanged.
> - AUR `commit-sage-bin` follows automatically on release.
> - Building from source now needs Bun 1.4.x instead of Deno.
> - `commit.promptForRefs` is deprecated in favor of `commit.refs` — existing configs still validate, and nothing reads the old key anymore.

### What changes for users

- **Much smaller downloads.** Every binary shrinks 30–44%: Linux 165->93 MB, macOS 141->82 and 130->74 MB, Windows 141->99 and 135->86 MB.
- **Alpine and old-glibc support.** The new musl builds run where glibc builds refuse to start; the installer picks the right one automatically.
- **Nothing to relearn.** Flags, config keys, `commit-sage generate --offline` output, and exit codes (0/1/2/130) are byte-for-byte the same.
- **Same install flows.** `unix.sh`, DMGs, the Windows installer, and the AUR package all keep working; only direct Linux asset URLs change (see above).
- Config stays at `~/.config/commitSage/config.json`. One edge case: `XDG_CONFIG_HOME`/`XDG_CACHE_HOME` are now honored, so XDG-based setups may see the config/cache in the XDG location instead of the default.
- **More message styles.** Four new formats — `emojiKarma`, `google`, `atom`, `detailed` — bringing the catalog to 11. Each one works in all six built-in languages, so `commit-sage generate --format google --lang japanese` just works:

```bash
commit-sage generate --format emojiKarma
commit-sage config set commit.commitFormat detailed
```

- **Guidance that sticks.** If you find yourself repeating the same context every run, set it once and stop typing it:

```bash
commit-sage config set commit.customInstructions "Write in the imperative mood."
```

It is added to every format automatically. Point it at a `.md` file instead
and the file's contents are used — handy for team conventions that live in
docs.

- **Your language, even if it isn't listed.** `commitLanguage` now accepts
  anything, not just the six built-ins. The first run with a new language
  offers a one-time translation; after that it behaves like a native. No TTY
  or changed your mind? The run warns and exits cleanly instead of hanging,
  so scripts and pipes never break.

- **Issue IDs without retyping.** Enable refs once, and your ticket IDs attach themselves

```json
{
  "commit": {
    "refs": {
      "enabled": true,
      "source": "prompt",
      "value": "",
      "placement": "end",
      "branchPattern": "[A-Z][A-Z0-9]*-[0-9]+"
    }
  }
}
```

Working on `feature/PROJ-123-login`? Your message ends with `Refs: PROJ-123`
automatically. Prefer it elsewhere — above the message or on the subject
line — with `placement`. Rather decide per commit? `--ref PROJ-1 --ref
PROJ-2` stamps explicit IDs onto one run, and `--refs` asks you just this
once. Trying it out needs no config at all:

```bash
commit-sage generate --ref PROJ-123
```
