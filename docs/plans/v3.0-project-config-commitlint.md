# v3.0.0 — Project config, commitlint, single diff knob

Theme: the breaking umbrella. Everything that changes config shape lands here, once, with auto-migration.
Status: post-grill. Grill protocol: `grill-with-docs` rounds 1-2, 2026-10-05.

## Goal and user story

As a user, I want my repo to carry its own commit conventions (checked in, shared with the team), generated messages validated against real commitlint rules without ever blocking my commit, and one diff-mode knob instead of two keys steering one decision.

## Exact CLI surface

- `config init [--global]`: writes `.commitsage/config.json` in CWD (default) or rewrites the global file from the scaffold (`--global`). Existing file ⇒ `overwrite? y/n`, never silent clobber. Exit 0 on write or on decline.
- `config set <key> <value> [--project]`: `--project` writes the project file (creating `.commitsage/` if needed); default writes global. `providers.<name>.models` presets stay global-only (deep maps don't merge; documented).
- `config get <key> [--source]`: `--source` reports which layer the value came from (`flag | project | global | default`). Merged view otherwise.
- `generate [--config <path>]`, `commit [--config <path>]`: the file is the whole config (ADR 013). No project overlay, no trust gate (pointing is consent). Missing path ⇒ exit 2; invalid file ⇒ exit 1.
- No new flags on `generate`/`commit` for commitlint: `commit.commitlint.*` config drives it. Validation failure ⇒ warn + use as-is (ADR 014), exit 0.

Exit codes: 0 success / 1 error / 2 usage / 130 abort, unchanged. Non-TTY: trust prompts never happen (sensitive project keys ignored + warn); commitlint project engine requires prior TTY approval (untrusted ⇒ builtin fallback + warn); `--offline` ignores project overlays only in the sense that formats never applied offline — diff mode still resolves through the merged config.

## Config deltas

| Key | Type | Default | Notes |
|---|---|---|---|
| `commit.onlyStagedChanges` | — | — | **deleted** (ADR 011). Migration: `auto` + `false` ⇒ `diffStrategy: "unstaged"`; else drop key |
| `generation.diffStrategy` | enum | `"auto"` | unchanged values; `auto` now means staged-iff-staged-exists, no second key |
| `commit.commitlint.enabled` | boolean | `false` | master switch |
| `commit.commitlint.engine` | enum `builtin\|project` | `"builtin"` | `project` shells the repo's own commitlint CLI |
| `commit.commitlint.maxRetries` | number | `3` | LLM refine attempts; then warn + use as-is |
| `commit.commitlint.rulesPath` | string | `""` | explicit rules file/dir; empty ⇒ auto-discover from repo root |
| `commit.promptForRefs` | boolean | `false` | stays a deprecated no-op (kept for compat, never read) |

Breaking: exactly one deletion (`onlyStagedChanges`). Everything else additive. Migration mirrors v1→v2: `migrateConfig` rewrites in one pass, batched warnings, `config list` review hint, second run silent. Legacy `config set commit.onlyStagedChanges <bool>` maps to `diffStrategy` (`false` ⇒ `unstaged`, `true` ⇒ `auto`) with a deprecation warning.

### Behavior changes

- Load order: flags > project (`.commitsage/config.json` walked CWD→git root, ADR 010) > global > compiled defaults. Project file missing ⇒ skip silently. Project parser is lenient (partial object, unknown keys pass through, type mismatches dropped + warn, `__proto__` guards); global parser stays strict.
- Trust gate (ADR 012): first TTY run with a project file lists sensitive keys (endpoint/`baseUrl`, `useApiKey`, `models` presets, `autoCommit`/`autoPush`, commitlint engine/rulesPath) and asks to trust. Approval hash (`machine-id | os | remote-or-"<no-remote>"`) appended to `$XDG_CACHE_HOME/commitSage/trusted`. Untrusted (or non-TTY): sensitive keys ignored + warn, rest applies.
- Commitlint builtin: upstream rule tables for all 11 formats, injected into the prompt when enabled; mechanical auto-fix (type case, trailing period, blank line before body); refine loop to `maxRetries`; skipped for `custom`-era... no `custom` format exists (deferred per ADR 006) — skipped for `previous` only, plus any format with empty rule handling per upstream (`emoji`/structural go straight to LLM refine).
- Commitlint project engine: discover `node_modules/{commitlint,@commitlint/cli}` upward from repo root; validate via stdin spawn (30s SIGKILL timeout); `--print-config` rules; failure ⇒ warn + builtin fallback. `Deno` has no `require()` of repo config; CLI spawn only.
- `config open/edit/path/default` stay global-targeted; `config list` shows merged view (documented). `set --project` creates `.commitsage/` as needed.

## File-level implementation sketch

- `src/services/config.ts` — `migrateConfig`: add pass 7 (`onlyStagedChanges` ⇒ `diffStrategy`, delete key); `load()`: discover + lenient-parse + trust-filter + merge project over global before `get()`/`resolveProviderValue` see it; `set`: `--project` target + legacy `onlyStagedChanges` map.
- `src/services/projectConfig.ts` (new): `findProjectConfig()` (CWD→git-root walk), lenient `parseProjectConfig()` (strip `//` comments + trailing commas, partial merge, warn-and-drop on mismatch), `TRUST_SENSITIVE_KEYS` list.
- `src/services/projectTrust.ts` (new): fingerprint readers per OS, SHA-256 hash, cache-file append/check, TTY approval prompt. Non-TTY ⇒ no-op (deny-sensitive).
- `src/lib/types/config.ts` + `constants.ts` + `configValidation.ts` + `configSchema.ts`: delete `onlyStagedChanges` everywhere (type, defaults, Zod, schema tuples, `TYPE_MAP` in `cli/config.ts` → deprecation shim); add `commitlint.{enabled,engine,maxRetries,rulesPath}`; `mask schema build`.
- `src/services/ai.ts` — `resolveDiffMode()`: drop the `onlyStagedChanges` branch; `auto` ⇒ `hasStaged ? staged : unstaged`. Commitlint: inject rules into prompt when enabled; post-generation validate → auto-fix → refine loop in `generateCommitMessage`.
- `src/cli/commit.ts` gate (~line 158): key off resolved mode (`staged && !hasStaged` ⇒ exit 0 message), not a config re-read.
- `src/services/commitlint/` (new): `tables.ts` (per-format rule sets ported from upstream, attributed), `validator.ts` (header/type/scope/subject checks), `autoFix.ts` (mechanical fixes), `projectEngine.ts` (CLI discovery + spawn + `--print-config` parse + timeout).
- `src/cli/config.ts` — `init` subcommand, `set --project`, `get --source`.
- `src/cli/flags.ts` + `generate.ts`/`commit.ts` — `--config <path>` plumbed to load.
- Scaffold content (`config init`): `$schema` + `model` + full `commit` + full `generation` + one `providers.gemini` placeholder (`apiKey: "$GEMINI_API_KEY"`, model placeholder).

## Test plan

- Unit: migration matrix (all 6 `diffStrategy × onlyStagedChanges` combos + absent key; idempotence: second run silent); lenient parser (partial, comments, trailing commas, `__proto__` dropped, mismatch dropped + warn); trust hash determinism (same remote new path ⇒ same hash; remote change ⇒ mismatch); `--config` replaces (project file present but ignored); reasoning of `get --source` per layer.
- Integration (tmp repos + git remotes): walk-up discovery finds root file from subdir; TTY approval flow stores hash; non-TTY ignores sensitive + warns; `config init` scaffold validates; overwrite prompt declines safely; commitlint builtin catches bad type-case and auto-fixes; project engine shells a fixture `node_modules/.bin/commitlint` stub; timeout kills a hanging stub (SIGKILL); untrusted repo falls back to builtin.
- Fixture diff tests: golden rule-table outputs per format; prompt-injection rendering with rules appended.
- Schema: `mask schema check` green; old configs with `onlyStagedChanges` migrate on first run.

## Resolved grill findings

1. Directory-only layout, no legacy file, no `templates/` in M4 (ADR 010, round 2 Q1→C).
2. `set --project` + `get --source`; models presets global-only (round 1 Q2→A).
3. Trust: path excluded from hash; machine fingerprint salt; XDG cache store; non-TTY degrades (ADR 012, round 2 Q3 modified).
4. Both commitlint engines, fail-open (ADR 014, round 1 Q4→A).
5. Consolidation-doc migration folded into the v3 pass (ADR 011, round 1 Q5→A).
6. Scaffold: full needed fields + `$schema`, Gemini placeholder, no comments (round 2 Q4→A modified).
7. `--config` replaces whole config (ADR 013, round 2 Q2→B).

## Open questions for the maintainer

1. Scaffold `model` value: placeholder `gemini/<model>` vs a concrete default Gemini model id. Needs the current default Gemini model string (extension default unknown to this plan).
2. `config open/edit/path/default/list` stay global: `list` shows merged view — should `list --source` (per-key layer annotations) exist, or is `get --source` enough?
3. CI escape hatch: should an env var (e.g. `COMMIT_SAGE_TRUST_PROJECT=1`) approve project-sensitive keys non-interactively, or is `--config` the only automation path? Plan chooses `--config`-only; the env var is one line if wanted.
4. `rulesPath` pointing at a file vs directory: plan accepts either (file ⇒ use it, dir ⇒ discover inside). Confirm.
