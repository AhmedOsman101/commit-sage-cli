# v2.4.0 — Customization

Theme: user voice (instructions, language, formats) + refs footers.
Status: post-grill. Grill protocol: `grill-with-docs` rounds 1-2, 2026-10-05.

## Goal and user story

As a user, I want the generator to follow permanent guidance I set once,
write in a language I actually use, pick from the same format catalog the
extension offers, and attach issue IDs to my messages without retyping them.

## Exact CLI surface

New flags (both `generate` and `commit` unless noted):

- `--ref <token>` (repeatable): override the configured refs source for
  this run with explicit tokens. Accepts any string, free-form. Repeatable:
  `--ref PROJ-1 --ref PROJ-2` renders both.
- `--refs`: force a single interactive prompt for refs even when
  `commit.refs.source` is `branch` or `input`. TTY-only; non-TTY with no
  resolvable tokens warns and skips (never errors, preserving pipe-ability).
- All new behavior is non-interactive-safe: unknown-language translation
  prompt counts as declined on non-TTY (warn + exit 0, see below).

Exit codes unchanged: 0 success / 1 error / 2 usage / 130 abort.

## Config deltas

| Key | Type | Default | Notes |
|---|---|---|---|
| `commit.commitFormat` | enum | `"conventional"` | gains `emojiKarma`, `google`, `atom`, `detailed` (`previous` arrived in M1; total 11) |
| `commit.commitLanguage` | string | `"english"` | six native templates now (`english/russian/chinese/japanese/german/french`); any other well-formed string is a custom language (on-demand translation, cached) |
| `commit.customInstructions` | string | `""` | inline text or path to a `.md` file (`.md` suffix + exists ⇒ read the file); injected as `## Custom Instructions` for every format |
| `commit.refs.enabled` | boolean | `false` | master switch; refs processing skipped entirely when false |
| `commit.refs.source` | enum `prompt\|branch\|input` | `"prompt"` | `branch`: regex-extract from current branch; `input`: use `commit.refs.value`; `prompt`: ask once |
| `commit.refs.value` | string | `""` | fixed token(s) for `source: input`; comma/space separated |
| `commit.refs.placement` | enum `end\|start\|prefix` | `"end"` | `end`: own line below; `start`: own line above; `prefix`: prepend to subject line |
| `commit.refs.branchPattern` | string | `"[A-Z][A-Z0-9]*-[0-9]+"` | regex over the branch name; first capture group wins, else full match |
| `commit.promptForRefs` | boolean | `false` | deprecated no-op: kept in schema for compatibility, never read (ADR: superseded by `commit.refs.*`) |

Additive only. No migration. Distinct from the extension on purpose:
`customLanguageName` is dropped (per ADR 003, `commitLanguage` alone
drives custom languages); there is no `useCustomInstructions` toggle —
non-empty `customInstructions` means enabled.

### Behavior changes

- Custom instructions render as a `## Custom Instructions` section for
  every format, including `custom`-era built-ins. Empty string ⇒ section
  omitted, zero overhead.
- Custom language flow: `commitLanguage` matches a native template ⇒ use
  it. Matches a cached `translations.json` entry ⇒ use silently. Neither ⇒
  interactive yes/no prompt ("translate with AI?"). Yes: translate via the
  configured provider, cache under `[language][format]`, continue. No — or
  non-TTY — : `Log.warn` + exit 0. Invalid regex in `branchPattern` ⇒ fall
  back to the default pattern (mirrors the extension).
- Refs source resolution: `branch` with no regex match ⇒ ref silently
  omitted. `prompt` cancelled by the user ⇒ generation aborts (exit 130
  path, same as other confirms). `--ref` wins over `--refs`, which wins
  over config source.
- Refs render as `Refs: <a>, <b>` (ADR 004), placed per `placement`.
  Appended post-generation, before preview and before `--edit` handoff, so
  the editor sees the final text.
- Offline generator: unchanged, conventional-only. Formats and refs do not
  apply to `--offline`.

## File-level implementation sketch

- `src/lib/types/commit.ts` — extend `COMMIT_FORMATS` (~line 16-25) with
  the 4 new formats; extend `SUPPORTED_LANGUAGES` (~line 1-6) with
  `german`, `french`.
- `src/templates/formats/` — add `emojiKarma.ts`, `google.ts`, `atom.ts`,
  `detailed.ts`, each a `Record<CommitLanguage, string>` over the 6 native
  languages (ported from the extension's templates, attribute per README).
  Register in `src/templates/index.ts` (~line 16-23). `getTemplate`
  fallback (~line 31-45) stays: unknown language ⇒ English + warning.
- `src/lib/types/config.ts` — add `customInstructions: string`,
  `refs: { enabled, source, value, placement, branchPattern }` to
  `CommitConfig` (~line 22-31); keep `promptForRefs` (deprecated).
- `src/lib/constants.ts` — mirror defaults in `DEFAULT_CONFIG`.
- `src/services/configValidation.ts` + `src/lib/types/configSchema.ts` —
  extend Zod + schema tuples; deprecation note on `promptForRefs`;
  `mask schema build`.
- `src/services/prompt.ts` — read `customInstructions` (resolve `.md`
  path vs inline), render the section; read `commitLanguage` through the
  native → cache → prompt flow; new `translations` loader module
  (`~/.config/commitSage/translations.json`, tolerant of missing file).
- `src/services/refUtils.ts` (new) — `extractRef(branch, pattern)`:
  first capture group wins, else full match, invalid regex ⇒ default
  pattern. `src/services/refStore.ts` is NOT ported (no per-branch
  workspace state in a CLI; `source: input` covers the fixed-value case).
- `src/cli/flags.ts` + `src/cli/types/generateOptions.ts` — pick up
  `opts.ref` (array) / `opts.refs` (boolean); `validateOptions` keeps
  `--lang` as non-empty string (custom languages must pass validation).
- `src/cli/commit.ts` (~line 176-199) + `src/cli/generate.ts`
  (~line 156-172) — resolve refs post-generation, pre-preview;
  `splitMessage` interplay: footers append to the body, `prefix` placement
  prepends to the subject.
- `src/cli/config.ts` — `TYPE_MAP` gains the new keys; `coerceValue`
  unchanged (string/boolean only for these).

## Resolved grill findings

1. Custom languages use `commitLanguage` alone; `customLanguageName`
   dropped (ADR 003).
2. Translation prompts on unknown language; decline or non-TTY ⇒ warn +
   exit 0 (ADR 003).
3. Cache invalidation is manual: delete the entry, next run re-translates
   (ADR 003).
4. `customInstructions`: inline string or `.md` path (ADR 005).
5. `custom` single-umbrella format dropped; named template files deferred
   to their own round (ADR 006).
6. Full 4 formats × 6 languages ported (Q4-B), no English-only shortcut.
7. `Refs:` labeled footer, not raw tokens (ADR 004).
8. Template directory out of M2; `commitFormat` stays a closed enum (ADR 006).
9. Commitlint waits for M4 (Q7-A); output-cleanliness issues (duplicated
   messages, fenced blocks) already handled by `messageSanitizer`, noted
   but not driving M2 scope.

## Open questions for the maintainer

1. Translation call budget: translating one language fills only requested
   formats on demand (chosen). A `--translate-all-formats` prefill is not
   planned; flag if wanted.
2. `source: input` with multiple tokens: accepted as comma/space separated
   in `commit.refs.value` (chosen). Alternative was single-token only.
3. `prefix` placement + `--max-length`: prefixed subject may exceed the
   limit. Plan does not re-truncate after prefixing; flag if it should.
