> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `model: "provider/model"` + `providers` registry + per-model presets + `generation` renames + BCP-47 language + `apiKey`/`reasoning`/`apiType` + tokenizer, with automatic migration and `--model` flag, keeping `config get/set` shallow.

**Architecture:** Refactor the single `ConfigService` seam (schema, validation, migration, persistence) to the new `providers` shape; add a small `TokenCounter` util for `maxPromptTokens`; wire `providers.<name>.models` presets with per-value fallback `model > provider > defaults`; expose the new `model` string via `ConfigService` and `generate`/`commit` `--model` flag.

**Tech Stack:** Deno + TypeScript, `zod` for schema, `js-tiktoken` or `gpt-tokenizer` (spike smallest with `deno compile`), `lib-result` Result, Cliffy `Command`, `src/lib/constants.ts` `DEFAULT_CONFIG`, `src/services/configValidation.ts`.

```ts
// src/lib/utils.ts (or new src/lib/modelString.ts if tiny file justified)
export function splitProviderModel(s: string) {
  const i = s.indexOf("/");
  if (i <= 0 || i === s.length - 1) return ErrFromText(`Invalid model "${s}": expected "provider/model"`);
  return Ok({ provider: s.slice(0, i), model: s.slice(i + 1) });
}
```
