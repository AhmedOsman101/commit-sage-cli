# v2.3.0 — Prompt intelligence

Theme: better style mimicry, no silent file drops, no truncated messages.
Status: post-grill. Grill protocol: `grill-with-docs` round 1, 2026-10-05.

## Goal and user story

As a user, I want the generated commit message to sound like my repo's own
history, to see every changed file represented in the generation prompt even
when the diff is large, and to never get a half-finished AI response because
the output budget was too small.

## Exact CLI surface

No new commands or flags. Behavior changes only, all opt-out-able via config.
Exit codes unchanged: 0 success / 1 error / 2 usage / 130 abort. Non-TTY
behavior unchanged: `--offline` fully non-interactive; recent-commit gathering
is pure `git log`, no prompts.

## Config deltas

| Key | Type | Default | Notes |
|---|---|---|---|
| `commit.commitFormat` | enum | `"conventional"` | gains `"previous"` member |
| `commit.recentCommitsEnabled` | boolean | `false` | inject recent commit messages as style examples into the prompt |
| `commit.recentCommitsCount` | number | `5` | max examples injected; hard cap 20 |
| `commit.recentCommitsScope` | enum `"all"\|"mine"` | `"all"` | `"mine"` filters to the current user's commits |
| `generation.maxOutputTokens` | number | `4096` | global default; per-provider `providers.<name>.maxOutputTokens` and model presets override (existing precedence chain) |
| `git.timeoutMs` | number | `30000` | new top-level `git` section; bounds every git subprocess (diff, status, blame, log) |

Additive only. No migration. Existing v2.2.0 configs load unchanged;
`mask schema check` must pass after regenerating via `mask schema build`.

### Behavior changes

- `previous` format: builds the `conventional` template plus a
  `## Recent commit examples` block. When zero usable examples exist, warn
  once and fall back to the plain `conventional` template. `previous` never
  hard-fails on empty history.
- `commit.recentCommitsEnabled=true` appends the same examples block to
  whatever format is selected (format and examples are orthogonal, matching
  the extension's `useRecentCommitsAsContext`).
- Token budget: `generation.maxPromptTokens` becomes a budget over the whole
  prompt (diff + blame + examples), not just the diff. Reduction order when
  over budget: drop/shrink examples first, then blame, then the diff. Each
  reduction emits one `Log.warn` line naming what was reduced.
- File-aware truncation replaces the head-slice at `src/services/ai.ts:72`:
  the diff is split per file (`src/services/git.ts:174-300` join points),
  low-value files (lockfiles, generated, minified) truncated first, each
  remaining file gets a fair share, cuts land on line boundaries with a
  `...(truncated)` marker.
- Blame respects its share of the budget: cap per-file changed-line count
  before tokenization, truncate the rest, warn once with affected paths.
- AI output budget: `maxOutputTokens` is resolved (model preset → provider →
  `generation.maxOutputTokens` → 4096) and passed through
  `ModelService.getGenerationOptions` into every provider's `generateText`
  call. A response that ends for length (`finish_reason: "length"` or
  equivalent) is retried with the budget doubled, up to 32768, at most 3
  bumps, layered on the existing retry/backoff.
- `git.timeoutMs` applies to diff/status/log/blame subprocesses. A blame or
  recent-commits timeout degrades to empty with a warning (the extension
  already degrades blame to `""`). A diff timeout is a hard error (exit 1).

## Resolved grill findings

1. Recent-commits scope: `all | mine`, matching the extension; no new modes.
2. Defaults: enabled=false, count=5, cap 20, noise filter at ≥20 chars
   (user tightened from the extension's 10-char threshold to avoid
   false-positive drops).
3. `previous` lives in the `commitFormat` union, not a side key; empty
   history warns and falls back to `conventional`.
4. Token budget is shared across the whole prompt; reduction order is
   examples → blame → diff, each step warned. Tweakable later.
5. `maxOutputTokens` wired through `getGenerationOptions`, default 4096,
   ceiling 32768, doubling ladder, truncation-as-failure retry.
6. `git.timeoutMs` is the new single git-subprocess timeout; AI timeout
   stays at `providers.defaults.timeoutMs`.
7. Blame degrades with a warning on budget exhaustion or timeout, unlike the
   extension's silent degrade.

## Open questions for the maintainer

1. Flat keys (`commit.recentCommitsEnabled/Count/Scope`) vs nested
   `commit.recentCommits: {...}`. Chose flat because `config set/get` is
   deliberately shallow (README: "`config get/set` stays shallow by design").
2. New top-level `git` config section for `timeoutMs`. Alternative:
   `generation.gitTimeoutMs`. Chose `git.timeoutMs` for extensibility
   (future git knobs); breaks no convention since `providers` is also a
   top-level section.
3. `maxOutputTokens` ceiling 32768 hardcoded as a constant vs configurable.
   Plan hardcodes it; flag if you want it exposed.
4. The pre-existing un-awaited `hasChanges` calls at `src/services/git.ts:179-183`
   were noted during exploration. Out of M1 scope; recommend a separate
   `fix:` commit.
