# 0012 — Project-trust approvals live in the cache dir, keyed without path

First run in a repo with a project file lists the trust-sensitive keys found and asks to trust (TTY only). Approval is a SHA-256 hex line in `$XDG_CACHE_HOME/commitSage/trusted` (platform equivalent on macOS/Windows) over `machine-id | os-name | git-remote-url-or-"<no-remote>"`. The repo path is deliberately excluded: moving a clone must not invalidate trust. The machine fingerprint (`/etc/machine-id`, `IOPlatformUUID`, `MachineGuid`) is read, never written; only hashes are stored, pinned so entries verify across CLI versions. Non-TTY runs never prompt and never read the fingerprint: sensitive keys are ignored with a warning, the rest applies. Automation uses explicit `--config` instead. Deleting the cache file revokes everything. Chosen over always-apply (a cloned repo could exfiltrate via `baseUrl` before any warning is read) and over never-apply (per-project gateways are the main use case).
