# Config V2 — Unified Model String, Providers Registry & Generation Renames

> **Status:** Draft — grilling closed 2026-08-04, awaiting plan + tickets  
> **Date:** 2026-08-04  
> **ADR:** [`docs/adr/002-config-v2.md`](../adr/002-config-v2.md) — grilling decisions  
> **Replaces:** `provider.type` + `provider.model`, top-level `ollama`/`openai`/`openrouter`, `general` section, `commit.maxSubjectLength`, `commit.commitLanguage` strict long-form

---

## Problem Statement

`commit-sage`’s config grew organically around a single-AI-call model and never learned the patterns users now expect from router-aware CLIs (`opencode`, `pi`):

1. **Two keys for one intent.** `provider.type` + `provider.model` must stay in sync. Multi-segment model ids like `9router/kc/stealth/ox-alpha` don’t fit — `model` contains slashes that encode a router + sub-path, but `provider.type` is asserted separately and the two can drift.

2. **Per-provider transport is scattered.** `ollama.baseUrl`, `openrouter.baseUrl`, `openai.baseUrl` + `openai.apiKeyEnvVar` + `openai.useChatCompletions` live as unrelated top-level sections. Adding a new router (`9router`) means adding a new top-level section and touching validation, defaults, and `TYPE_MAP` in three places. There is no single `providers` registry to browse with `config list` or extend via presets.

3. **API key env var is privileged.** Only `openai.apiKeyEnvVar` is configurable; every other provider is hard-coded to `${NAME}_API_KEY`. Users who run `ollama`/`vllm`/`llamacpp` locally or who store keys literally in config have no option, and routers that expose `$N9ROUTER_API_KEY` must use the `openai` section as a workaround.

4. **Language is strict long-form.** `commit.commitLanguage` accepts only `english`/`russian`/`chinese`/`japanese`. Users naturally type `en`, `jp`, `en-US` or `ja-JP` and get a validation error. Adding 9+ languages with a closed long-form enum will make the table tedious.

5. **Naming is ambiguous.** `commit.maxSubjectLength` reads as “max of what?” — callers must remember it caps the subject line only. `general` reads as “general what?” — its fields (`maxRetries`, `temperature`, `maxInputChars`, `diffStrategy`) all affect generation and belong under `generation`.

6. **No per-model tuning.** There is no place to say “`gpt-5-nano` uses `reasoning:false` but `kc/stealth/ox-alpha` needs `reasoning:high` and a 1M `contextWindow`”. `opencode` and `pi` both ship `models: { "id": {limit, reasoning, …}}` presets for this; `commit-sage` has none.

Without fixing these, every new provider or model adds schema debt, the config file keeps diverging from the mental model `provider/model`, and token limits are still counted in characters.

---

## Solution

Collapse `provider.type` + `provider.model` into a single top-level `model: "provider/model"` string, collect all per-provider transport under one `providers` registry, and rename the ambiguous sections/keys. Presets, BCP-47 language, and token counting ship with the same release so the config language stays coherent.

The user-visible result:

- **`model: "openai/gpt-5-nano"`** is canonical. Split on the **first** `/` — left is provider, right is model (whatever remains, including further slashes like `kc/stealth/ox-alpha`). Fail only if no `/`, empty model part, or provider not in the open registry.

- **`providers: { defaults, ollama, openai, 9router, … }`** is the registry. `providers.defaults` holds global AI defaults (`timeoutMs`, `reasoning`, `apiType`, `contextWindow`, `maxInputTokens`, `maxOutputTokens`). `providers.<name>` holds `baseUrl`, `apiKey` (`"$ENV_VAR"` → env, else literal), `apiType`, plus per-provider overrides. `providers.<name>.models."<id>"` holds per-model overrides (`name`, `reasoning`, `contextWindow`, `maxInputTokens`, `maxOutputTokens`, `temperature`).

- **`apiKey: "$OPENAI_API_KEY"`** works for every provider. `$`-prefix means “read from env”; without `$` the value is taken literally from the config file. For local providers (`ollama`, `llamacpp`, `vllm`) the key is optional (`null`/`""`/absent = no auth).

- **`reasoning: boolean | ProviderReasoning`** — `false`/`off` = no reasoning, `true`/`default` = provider default, otherwise explicit level (`low`/`medium`/`high`/`xhigh`/`ultra`). Tri-state, not just boolean.

- **`apiType: "openai-chat" | "openai-responses" | "anthropic"`** — merges `useChatCompletions` + `api`. Chat Completions vs Responses for OpenAI-compatible, single type for Anthropic-compatible.

- **`commit.commitLanguage`** stores whatever the user gave — `en`, `english`, `en-US`, `ja`, `jp`, `japanese` are all valid (BCP-47, A3). `ja` and `jp` both alias Japanese; canonical is whatever was set, not forced to long form.

- **`generation`** replaces `general`; `commit.maxLength` replaces `commit.maxSubjectLength`; `retryDelay` replaces `initialRetryDelayMs`; `maxInputChars` → `maxPromptTokens` (tokens via small tokenizer, not characters). Hard rename with automatic migration and a batched warning.

- **`model > provider > defaults` per-value fallback** — e.g. a preset `reasoning:false` wins, but its missing `maxInputTokens` falls back to `providers.<name>.maxInputTokens`, then `providers.defaults.maxInputTokens`, then `DEFAULT_CONFIG`.

- **`config get/set` stays shallow** for `providers.*.models` — deep preset editing is done via `config edit` (documented limitation).

The old shape keeps working for one load via automatic migration (refactored `migrateConfig`, warnings batched, no silent data loss).

## User Stories

### Unified `model` string
1. As a user, I want to set `model: "openai/gpt-5-nano"` as a single string, so I don’t maintain `provider.type` + `provider.model` in sync.
2. As a user of a router, I want `model: "9router/kc/stealth/ox-alpha"` to work (provider `9router`, model `kc/stealth/ox-alpha`), so multi-segment model ids are first-class.
3. As a user, I want `commit-sage config set model openai/gpt-5` to persist the canonical string, so the CLI matches the file.
4. As a user, I want `commit-sage generate --model 9router/kc/stealth/ox-alpha` to override the config for one run, so I can try a model without editing the file.
5. As a user, I want a clear error if I set `model: "openai"` (no slash) or `model: "openai/"` (empty model), so I notice the typo immediately.

### `providers` registry
6. As a user, I want all per-provider transport under `providers: { openai: {baseUrl, apiKey, apiType}, ollama: {…} }`, so I can see every provider in one place with `config list`.
7. As a user, I want `providers.defaults` to hold global AI defaults (`timeoutMs`, `reasoning`, `apiType`, `contextWindow`, `maxInputTokens`, `maxOutputTokens`), so I don’t repeat them per provider.
8. As a user, I want `providers.9router.baseUrl` to be addable without code changes (open registry via `"foo" | (string & {})`), so custom routers work.
9. As a user, I want `providers.ollama.baseUrl` and `providers.openai.baseUrl` to migrate automatically from the old top-level `ollama`/`openai`/`openrouter` sections, so my old config isn’t lost.
10. As a user, I want any top-level `providers.<name>` not in the known enum to be accepted if it has a valid shape, so local forks (`llamacpp`, `vllm`) work.

### `apiKey` for all providers
11. As a user, I want `providers.openai.apiKey: "$OPENAI_API_KEY"` to read from the env, so secrets stay out of the file.
12. As a user, I want `providers.openai.apiKey: "sk-…"` to be taken literally, so I can check in a dummy key for tests.
13. As a user, I want `providers.gemini.apiKey: "$GEMINI_API_KEY"` to work the same way, so I’m not limited to OpenAI.
14. As a user running Ollama locally, I want `providers.ollama.apiKey` to be optional (`null`/`""`/absent = no auth), so I don’t set a fake env var.

### Per-model presets
15. As a user, I want `providers.openai.models."gpt-5-nano": {name, reasoning, contextWindow, maxInputTokens, maxOutputTokens, temperature}` to override per provider, so I can tune `reasoning:false` for one model and `reasoning:high` for another.
16. As a user, I want presets to inherit per-value (`model preset > provider > defaults`), so a preset with only `reasoning:false` still inherits `maxInputTokens` from its provider.
17. As a user, I want `providers.openai.models` to be a map (`Record<modelId, preset>`), so `config edit` is discoverable via JSON.

### `apiType`
18. As a user, I want `providers.openai.apiType: "openai-responses"` to call the Responses API, so I can use models that require it.
19. As a user, I want `providers.openai.apiType: "openai-chat"` (default) to call Chat Completions, so existing OpenAI configs keep working.
20. As a user, I want `providers.anthropic.apiType: "anthropic"` (single type) to work, so Anthropic-compatible providers are not forced into OpenAI branching.

### Language BCP-47
21. As a user, I want `commit-sage config set commit.commitLanguage en` and `english` to both be valid and stored as-given, so I can use short or long form.
22. As a user, I want `commit-sage config set commit.commitLanguage en-US` or `ja-JP` to be accepted (BCP-47), so regional tags work.
23. As a user, I want `jp` and `ja` to both mean Japanese, so the popular `jp` alias doesn’t error.
24. As a user, I want short codes to expand to 9+ languages without a second alias table, so future languages just work.

### Renames
25. As a user, I want `generation` instead of `general`, so the section name says it affects generation.
26. As a user, I want `commit.maxLength` instead of `commit.maxSubjectLength`, so the key is unambiguous.
27. As a user, I want `generation.retryDelay` instead of `generation.initialRetryDelayMs`, so the name is shorter.
28. As a user, I want `generation.maxPromptTokens` instead of `generation.maxInputChars`, counted via a tokenizer, so limits match LLM token windows.
29. As a user, I want old keys (`general`, `maxSubjectLength`, `initialRetryDelayMs`, `maxInputChars`) to migrate automatically with a warning, so my old file doesn’t silently reset.

### Fallback & migration
30. As a user, I want per-value fallback `model preset > provider > defaults` for `reasoning`/`contextWindow`/`maxInputTokens`/`maxOutputTokens`/`temperature`/`timeoutMs`, so I can set a global default and override only what differs.
31. As a user, I want `commit-sage config list` to show the merged result after migration, so I can verify the new shape.
32. As a user, I want `commit-sage config edit` to validate the new shape and restore the old file on invalid JSON, so a bad edit doesn’t brick the config.

### CLI parity
33. As a user, I want `commit-sage config get model` to print `"openai/gpt-5-nano"`, so the active model is inspectable.
34. As a user, I want `commit-sage config get generation.retryDelay` to work after the rename, so the new generation keys are reachable.
35. As a user, I want `commit-sage config get commit.commitLanguage` to print whatever I set (`en` stays `en`), so short form isn’t forced to long.

### Tooling
36. As a user, I want `providers.<name>.models` deep presets to be intentionally out of scope for `config get/set` dot-path (shallow only, edit the file directly), so the CLI surface stays simple.

## Implementation Decisions

- **Top-level `model: "provider/model"` replaces `provider: {type, model}`.** Split on **first** `/`: `provider = s.slice(0, i)`, `model = s.slice(i+1)`. Fail if no `/`, empty model part, or provider part empty. Provider part validated against open union `"known" | (string & {})` — known providers get enum help, custom strings allowed (e.g. `9router`). No bare-provider fallback (always require `provider/model`).

- **`providers` registry.** New top-level `providers: { defaults, <name>: ProviderConfig }`. `defaults: { timeoutMs, reasoning, apiType, contextWindow, maxInputTokens, maxOutputTokens }`. Each `providers.<name>` has `baseUrl?`, `apiKey?`, `apiType?`, `timeoutMs?`, `reasoning?`, `contextWindow?`, `maxInputTokens?`, `maxOutputTokens?`, plus `models: Record<modelId, ModelPreset>`. Open registry: `providers` keys are `KnownProvider | (string & {})` via `"foo" | (string & {})` trick. Old `ollama`/`openai`/`openrouter` top-level sections deleted after migration.

- **`general` → `generation`.** Hard rename. `generation: { maxRetries, retryDelay, temperature, maxPromptTokens, diffStrategy, maxLength? }` — `retryDelay` was `initialRetryDelayMs`, `maxPromptTokens` was `maxInputChars` (now tokens). `timeoutMs` **removed** from `generation` (lives only in `providers.defaults` per Q16 A2). `temperature` stays in `generation` as global default and is overridable per model (Q14).

- **`commit.maxSubjectLength` → `commit.maxLength`.** Hard rename.

- **`apiKey` semantics.** Field renamed from `apiKeyEnvVar` to `apiKey`. If value starts with `$` → `Deno.env.get(value.slice(1))`; else literal from config. If `apiKey` absent or `null`/`""` and provider is local (`ollama`/`llamacpp`/`vllm`) → no auth required; otherwise fallback to `${NAME}_API_KEY` env. For non-local providers, missing env after `$` resolution is an error.

- **`reasoning: boolean | ProviderReasoning`.** `false`/`"off"` = no reasoning, `true`/`"default"` = provider default, otherwise explicit level `"low"`/`"medium"`/`"high"`/`"xhigh"`/`"ultra"`. `ProviderReasoning` kept as before, now unioned with boolean.

- **`apiType: "openai-chat" | "openai-responses" | "anthropic"`.** Merges old `useChatCompletions` + `api`. `openai-chat` = OpenAI-compatible Chat Completions, `openai-responses` = Responses API, `anthropic` = Anthropic-compatible single type. Default per provider family.

- **Language BCP-47, store-as-given.** `commit.commitLanguage` accepts `en`/`english`/`en-US`/`ja`/`jp`/`japanese` etc. (A3). Stored verbatim; PromptService normalizes to canonical prompt internally. `ja` and `jp` both alias Japanese. Future 9+ languages just extend the alias map; no schema enum lock.

- **Tokenizer for `maxPromptTokens`.** Replace char slicing (`maxInputChars`) with token counting. Introduce a small tokenizer (e.g. `js-tiktoken` or `gpt-tokenizer` — pick the smallest that covers the 9router model families; avoid `tiktoken` WASM if it bloats `deno compile`). Diff truncation: count tokens of the prompt diff, truncate at token boundary, not mid-character.

- **Per-model preset shape.** `ModelPreset: { name?: string, reasoning?: boolean|ProviderReasoning, contextWindow?: number, maxInputTokens?: number, maxOutputTokens?: number, temperature?: number }`. `name` is display name for future interactive picker. `Record<modelId, ModelPreset>` as map (not array) — matches `pi`/`opencode` but easier for JSON editing; `id` is the map key (which may itself contain `/` like `kc/stealth/ox-alpha`).

- **Per-value fallback chain.** For each of `reasoning`/`contextWindow`/`maxInputTokens`/`maxOutputTokens`/`temperature`/`timeoutMs`/`apiType`: `providers.<name>.models.<id>[key] ?? providers.<name>[key] ?? providers.defaults[key] ?? DEFAULT_CONFIG.providers.defaults[key] ?? DEFAULT_CONFIG.generation[key]`. Per key, not all-or-nothing (Q7).

- **`config get/set` depth limit.** `TYPE_MAP` covers top-level and `generation`/`commit`/`providers.<name>` shallow keys only. `providers.<name>.models` and deeper nesting are **intentionally** out of scope for `get/set` dot-path — edit via `config edit` / `config open`. Document as limitation.

- **Migration — refactor existing `migrateConfig`.** Not a new function. Detect old shape (`general`, `provider.type`/`model`, `ollama`/`openai`/`openrouter` top-level, `maxSubjectLength`, `initialRetryDelayMs`, `maxInputChars`) → move to new keys, delete old, set `changed=true`. After all moves, collect warnings array, write file once, then `Log.warning(warnings.join("\n"))` + `Log.info("Config migrated — review with: commit-sage config list")`. Fail only on empty model or invalid provider part; otherwise write and continue. Also normalize `commitLanguage` aliases (`jp`→`ja` canonical internally but store-as-given per Q10 A3 means no rewrite — just accept).

- **CLI flags.** `--model "provider/model"` replaces `--provider` + `--model` pair (Q9 A1). Keep deprecated `--provider` that warns and if both given, concatenates `provider/model` for one run. `--provider` deprecation warning: `"--provider is deprecated, use --model provider/model"`. Multi-segment model part preserved (split first slash only).

- **Seams.** Existing seams preferred, one high seam:
  - **Primary seam:** `ConfigService` (`load`/`get`/`set`/`migrateConfig`) + `ConfigValidationService` (Zod schema) — schema, validation, migration, persistence all in one seam. New `providers` shape lives here.
  - **Secondary seam (new, justified):** `TokenCounter` util (tokenizer wrapper) — isolated so `generate`/`commit` can switch `maxInputChars` → `maxPromptTokens` without touching `ConfigService`. Fewer seams ideal, but tokenizer is a distinct I/O-free pure function with its own library choice.
  - Existing `TYPE_MAP` in `src/cli/config.ts` becomes nested map for `providers` — extend, don’t replace.

## Testing Decisions

- What makes a good test: external behavior only — `commit-sage config get model` prints the canonical string, `commit-sage config set model openai/gpt-5` persists, `generate --model 9router/kc/stealth/ox-alpha` splits correctly, `generation.maxPromptTokens` truncation is token-counted, migration from old shape succeeds with warning. No unit tests for internal `splitProviderModel` shape — test the seam.

- Prior art: no tests in this migration (user opted out, smoke-only). If tests are added later, follow the existing `lib-result` Result pattern — assert `Ok`/`Err` via `result.isOk()`.

- Modules to test if/when: `ConfigService.migrateConfig` (old→new), `TokenCounter.count`, `ModelResolver.split` (first slash), `reasoning` tri-state normalization.

## Out of Scope

- `input`/`output` modalities, `attachment`, `npm` provider metadata from `opencode`/`pi` — not needed for text commit messages.
- Ordered `models` array vs map — map chosen for `config edit` ergonomics; array can be added later if interactive picker needs ordering.
- Full BCP-47 canonicalization to `en` vs `english` forced normalization — store-as-given (A3) keeps both.
- Deep `config get/set` for `providers.*.models` — intentionally excluded, use `config edit`.
- `inputTypes`/`outputTypes`/`attachments` from `pi` — not ported.
- New providers beyond the open registry — handled by open union, no code change needed.

## Further Notes

- **Tokenizer choice:** `js-tiktoken` (pure JS) vs `gpt-tokenizer` vs `tiktoken` (WASM). Prefer the smallest that covers `openai`/`anthropic`/`9router` families and works with `deno compile` (no native). Spike before ticket T2; document the pick in the plan.

- **Telemetry for migration:** after `migrateConfig` writes, `providers.defaults` and `generation` defaults are filled via `migrateSectionDefaults` — same pattern as T2.

- **Docs reorg already done (T8):** specs are `docs/specs/YYYY-MM-DD-*.md`, ADRs are `docs/adr/NNN-*.md`, agents are `docs/agents/*`. This spec follows that. Plans go in `docs/plans/`.
